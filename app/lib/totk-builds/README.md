# TOTK Autobuild catalogue

The catalogue and detail pages live under the existing game slug:

`/game/the-legend-of-zelda-tears-of-the-kingdom/builds`

`catalogue.json` is generated by `scripts/import-totk-builds.py`. Originals and
small gallery previews are stored in `public/totk-builds/`. Download links always
use the original file, with no runtime image optimization. File names include a
content hash. Source metadata and checksums are kept in
`docs/research/totk-builds-import.json`, outside the client catalogue.

## Import

Use Python 3.11+ with `beautifulsoup4`, `Pillow` and `zxing-cpp` installed:

```sh
python3 scripts/import-totk-builds.py --limit 600 --workers 2 --delay 0.4 --verify-qr
```

The importer discovers IDs from the public English sitemap and public HTML lists.
It ranks by positive test badge, then votes, then popularity. It excludes negative
scores, visible broken-build warnings, placeholder titles, unreadable/non-Autobuild
QRs and duplicate blueprint payloads. Only the selected originals and previews are
retained. HTTP responses are cached in `/tmp/finalboss-totk-import` so interrupted
runs can resume. Remove that task-specific cache before deliberately refreshing
upstream votes or content.

Offline QR decoding verifies a readable Nintendo blueprint link. It does not
check Nintendo server availability or prove that the build works inside the game.
The `tested` flag reflects the imported community badge, never a FinalBoss test.

## Frontend

Presentation reuses the existing FinalBoss game-hub headings, panels and gray/yellow palette.

The explorer searches names, descriptions, types and tags. Categories can overlap.
Budget caps exclude unknown costs; a zero cost remains valid. Search, category,
budget, test status, tag, sort and page are shareable URL parameters and restore
on browser back/forward navigation. The initial 24 cards render on the server;
the client filters the saved catalogue without upstream requests.

Every detail page is statically generated, has canonical metadata and escaped
JSON-LD, and is included in `/game/sitemap.xml`. Category and numbered listing
pages have their own SSR content, titles and self-referencing canonicals. Native
links expose every listing page without JavaScript. Internal search and compound
filter URLs get an `X-Robots-Tag: noindex, follow` header. Only the visible page's
items appear in the collection JSON-LD. Imported build descriptions are unchanged;
collection introductions and the cost/import FAQ are original interface copy.
Navigation links are present on
the game page, games index, mobile menu, desktop menu and footer.

## In-grid advertising

The catalogue has two Journey slots on a full 24-card desktop page (after 8 and
16 cards), or up to three below 1280px (after 6, 12 and 18). Lists with fewer than
12 cards have no in-grid slots, and at least four cards follow the last slot.
Markers sit in stable React islands and occupy complete grid rows. Empty targets
leave no large placeholder boxes. Existing global advertising settings are unchanged.

The current Journey 3.89.1 wrapper registers `.mv_slot_target[data-slot="content"]`
through its exposed `window.$adManagementConfig.web.fillHints()` function, which
is called once per animation frame when new islands mount. Targets activate only
after hydration, preventing early third-party DOM insertion from breaking React.
If the SDK is not ready yet, its normal initialization scans them. This is distinct from `.content_hint`,
which the Journey offering disables; no `content_hint` markers or competing
automatic content selector are added to this grid. The existing site-wide loader
is reused. Native collection/page links start a normal document lifecycle.

The public wrapper was inspected at:
`https://scripts.journeymv.com/tags/3.89.1/wrapper.min.js`.
Actual filled creatives and revenue require a live-site check after deployment.

## Validation

```sh
node --test tests/totk-builds/*.test.mjs
python3 tests/totk-builds/importer.test.py
npm run build
```

With a local Next server and Python Playwright/Chromium available:

```sh
TOTK_TEST_BASE_URL=http://127.0.0.1:3188 python3 tests/totk-builds/browser.py
TOTK_TEST_BASE_URL=http://127.0.0.1:3188 python3 tests/totk-builds/seo-ads-browser.py
```

The browser check blocks third-party ads and analytics, exercises filters,
pagination, history and deep links, verifies an actual original-image download,
checks 404s, and captures desktop/mobile screenshots under
`/tmp/finalboss-totk-screenshots`.
The SEO/ad check also uses a browser without JavaScript, validates pagination,
canonicals and facet response headers, and uses clearly marked synthetic boxes
to check ad-row geometry and React isolation. This is not an auction/fill test.
